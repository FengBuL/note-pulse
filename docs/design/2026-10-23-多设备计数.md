# 多设备计数（1.7.0）

## 问题

“每日新增字数”（`data.json` 的 `wordLog`）和每篇笔记的计数基线（`cache.json` 的 `logged`）都放在库里的插件目录，随 iCloud / Obsidian Sync / git 一起同步。每台设备在内存里各有一份，保存时整份覆盖对方：

1. **重复计数**：手机上写了 500 字，手机记了一次；Mac 的基线还是旧的，同步过来的文件变长了，Mac 再记一次。
2. **丢失**：两台设备都改了 `data.json`，后保存的那台覆盖先保存的，前者当天的记录没了。
3. **外部程序写的内容被算成写作**：AI 助手、脚本、导入工具直接写文件，看起来和手写一样。

## 做法：每台设备只记自己键盘上的字，看板相加（G-Counter）

- 每台设备第一次运行时生成一个设备 ID，存在本机 `localStorage`（不随库同步）。
- 每台设备只写自己的记录文件 `devices/<设备 ID>.json`：`{ name, wordLog, wordLogBig, updated }`。别的设备只读不写，所以不会互相覆盖。
- 看板把所有设备的记录按日期相加。
- **只有在这台设备的 Obsidian 编辑器里改动的笔记才计入。** 用 `editor-change` 事件记下“本机正在编辑的文件”；文件变化时，这个文件在名单里才把增量记到本机，不在名单里（同步进来的、外部程序写的）只更新基线。
- 基线（`cache.json`）仍然是共享的缓存，只用来减少重读；因为只有编辑过的设备会记增量，基线是否被别的设备覆盖不再影响计数。

## 自动合并

连着同一个库就自动合并，没有开关：

- 主记录：`devices/<设备 ID>.json`，每台设备只写自己的文件。
- 副本：`data.json` 的 `devices` 字段存所有设备的记录。有的同步服务（Obsidian Sync 文档没写清楚）不一定同步插件目录里的额外文件，但一定同步 `data.json`。
- 读取时两边按设备合并，每天取较大值（记录只增不减，较大的就是最新的；取最大值和次序无关、重复做不变）。写 `data.json` 之前先把磁盘上的副本合并进来，避免覆盖别的设备刚同步来的记录。
- 看板打开时每分钟比较一次 `devices/` 下文件的修改时间，变了就重新统计；Obsidian Sync 改了 `data.json` 会触发 `onExternalSettingsChange`，同样重新统计。

## 迁移

- 现有 `data.json` 里的 `wordLog` / `wordLogBig` 原样保留，当作“1.7.0 之前的记录”参与相加，不再写入。
- 1.7.0 之后的新增只写设备文件。
- 不回溯扣减历史数字：旧记录里已经混进去的重复和外部写入，没有可靠依据拆出来。

## 取舍

- 在别的编辑器（Typora、VS Code、手机上的其他 App）里写的字不再计入“写作”。这些改动仍会更新笔记总字数，只是不进每日新增。
- 新建笔记时如果是在本机编辑器里输入的，照常计入；外部程序新建的笔记不计入。
- “重置每日新增字数记录”清空所有设备的记录（删除设备文件），否则重置后别的设备的旧记录还会被加回来。

## 设置

- 设置里“数据”一节列出参与合并的设备（名称、最后更新），可以给本机改名。
